# Fill Hero v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Manifest V3 Chrome extension that works through a list of opted-in business domains, finds each contact form, fills it, auto-submits high-confidence forms at a rate limit, and queues everything else for manual review.

**Architecture:** Pure logic (domain parsing, field classification, form scoring, rate limiting, contact-link finding, CAPTCHA detection) lives in `src/lib/` as dependency-free modules tested with Node's built-in test runner. Thin browser glue lives in `src/background.js` (orchestration, storage, tabs), `src/content.js` (DOM read/fill/submit), and `src/popup/` (control panel). No build step.

**Tech Stack:** Chrome Extension Manifest V3, plain JavaScript (ES modules in `src/lib/`, classic scripts elsewhere), `chrome.storage.local`, `chrome.tabs`, `chrome.scripting`, Node 18+ `node:test` for unit tests.

**Spec:** `fill-hero-design.md` (in the working directory). Read it alongside this plan.

## Global Constraints

- Manifest V3 only; no remote code, no external network calls.
- Plain JavaScript; no build step, no framework.
- Auto-submit gap: minimum 60000 ms between submissions.
- Daily cap: 50 submissions per local calendar day.
- Random pre-submit delay: 2000–5000 ms.
- Never solve or bypass CAPTCHAs; any detected CAPTCHA sends the domain to the queue with reason `captcha`.
- Never submit a domain whose log entry status is `sent` or `sent?`.
- Submit only when the form score is `high`; otherwise queue with reason.
- Storage keys: `domains`, `profile`, `log`, `queue`, `settings`, `dailyCount`, `dailyDate`, `lastSubmitAt`, `dryRun`.

## Review Focus

1. **Bare or malformed domain input** (`example.com`, `https://example.com/`, `  Example.COM  `, `http://`, empty line): must normalize to one `https://host` or be rejected with a reason, never crash the run.
2. **No contact page found** (site has no contact link and `/contact` and `/contact-us` both 404): must log `queued` with reason `no-contact-page`, not `failed` silently.
3. **Form with a required field the extension cannot fill** (dropdown, checkbox consent, unknown custom field): must score `low`, never submit.
4. **Stop pressed mid-run:** the in-flight domain finishes or aborts cleanly, no further domains start, and the log stays consistent.
5. **Re-running the same list after a restart:** domains already `sent` or `sent?` are skipped; the daily count and last-submit time survive a service-worker restart.

### Task 3: Form scoring, CAPTCHA detection, and contact-link finding

**Files:**
- Create: `src/lib/score.js`
- Create: `src/lib/contactLinks.js`
- Test: `tests/score.test.js`
- Test: `tests/contactLinks.test.js`

**Interfaces:**
- Consumes: `classifyField` from Task 2 (`src/lib/fieldMap.js`)
- Produces:
  - Form descriptor: `{ fields: FieldDescriptor[], hasPassword: boolean, action: string }`
  - `scoreForm(form: FormDescriptor) -> { level: "high"|"low", reason: string, fieldMap: Record<string, number> }` where `fieldMap` maps a classification to the index of the field in `form.fields`. `high` requires a message field, an email field, and no `password` fields, and no `unknown` or `consent` fields that are `required`. Reasons: `ok`, `no-message-field`, `no-email-field`, `has-password`, `unmapped-required`, `consent-required`.
  - `detectCaptcha(domSignals: { iframeSrcs: string[], classNames: string[] }) -> boolean` (true if any src or class contains `recaptcha`, `hcaptcha`, or `turnstile`).
  - `findContactLinks(links: Array<{ href: string, text: string }>, baseUrl: string) -> string[]` returns absolute URLs on the same host whose text matches `/contact/i` or `/get in touch/i`, deduplicated, in order of appearance. Falls back to `[base + "contact", base + "contact-us"]` when none match.
